# DevToolNext UI 调研与规划

- 日期：2026-10-31
- 状态：供评审的设计方案，不代表已修改正式界面或交付新功能。
- 依据：设备工作台定位、串口首发、外部 AI/MCP、Windows EXE 与局域网共用 Web UI。
- 本轮产物：调研记录、信息架构、交互规范和独立可交互原型。

## 1. 设计结论

推荐“开发者设备工作台”：以终端为主工作区，左侧管理设备与会话，右侧按需打开操作证据，底部持续呈现采集与控制状态。

视觉采用克制的中性表面、清晰的细边界、单一品牌强调色，同时设计深浅主题。新颖性主要来自设备上下文、人机共享控制和可追溯操作的组织方式，而不是换一套色彩或堆叠装饰。

这次先确认布局、任务流程和状态，再进入组件实现。现有 EXE 与正式界面保持原样。

## 2. 当前界面的问题

| 问题 | 对实际工作的影响 | 改进 |
| --- | --- | --- |
| 大标题、英文装饰和编号占据工作区域 | 常用尺寸下可见输出减少 | 移除宣传式标题，保留紧凑设备上下文栏 |
| 固定连接参数表长期占左侧 | 连接后仍占空间，却缺少设备和会话导航 | 左侧改为设备列表；参数在连接对话框和详情抽屉修改 |
| 独立状态栏过宽，但大部分为静态说明 | 终端宽度减少，窄屏换行增多 | 简单状态压到底栏；右栏只显示当前操作证据 |
| 原始接收块逐条呈现 | 一个 D 与其后的 evice 会被拆成两行，阅读不连贯 | 日志视图按流增量解码和组行；HEX 才按原始数据块展示 |
| 明细字体小、色彩对比偏弱 | 长时阅读和中文识别疲劳 | 正文 13–14px，输出 14px，可缩放；不使用 7–9px 关键文字 |
| 未来能力以不可用导航长期占位 | 视觉复杂但无法完成动作 | 正式首版只显示已交付入口；扩展位置在方案中保留 |
| 只有计数，缺少明确的操作上下文 | 难以判断谁发的命令、当前在等什么 | 操作记录关联调用者、任务状态和证据范围 |

以上为对现有实现与截图的设计评审，不是用户测试结论。

## 3. GitHub 实际参考

本轮读取官方仓库 README、相关文档，并下载、打开实际截图进行观察；没有把 README 的功能列表当作 UI 评测。仓库截图可能来自历史版本，不能视为最新安装版的现状。本轮没有运行这些参考产品。

### 3.1 Tabby：内容优先的终端工作区

观察：顶栏会话标签、中心终端分屏，界面边框与装饰很少；大部分面积交给输出和输入。

借鉴：终端优先、会话上下文固定、工作区以后可分屏。

不照搬：截图展示的是历史 Terminus 外观；首版不做多种任意分屏，也不默认把所有设备能力压成终端。

### 3.3 Insomnia：操作与结果的邻接关系

观察：集合导航、操作编辑与响应相邻，操作状态、耗时和内容在同一上下文中；不同内容使用局部标签切换。

借鉴：一次设备操作对应一个响应范围，状态与证据靠近，详情按需展开。

不照搬：HTTP 请求/响应有清晰边界，串口可能夹杂持续日志，不能把某段时间内全部输出都宣称为命令结果。也不采用大量固定三栏占满的布局。

来源：[仓库](https://github.com/Kong/insomnia)、[实际截图](https://github.com/Kong/insomnia/blob/develop/screenshots/main.png)。

本地观察副本：ui-research/insomnia.png。

不照搬：首版不引入复杂浮动窗口、Ribbon 工具栏、三维图和无实际数据的仪表。仓库图为多窗口组合图，不是单一当前窗口截图。

## 4. 方向比较

| 方向 | 布局与特点 | 适合场景 | 取舍 |
| --- | --- | --- | --- |
| A 开发者设备工作台（推荐） | 设备导航＋主终端＋可收起证据栏＋状态底栏 | 长时间排障、人机协作、未来多接入 | 需要认真设计控制状态和证据关联 |
| B 极简终端 | 顶部会话标签，终端占满，功能使用浮层 | 高度依赖 CRT 键盘操作的用户 | 首版更精简，但多类仪器和协作信息容纳较弱 |
| C 实验室控制台 | 可组合波形、参数和控制面板 | 多仪器测量、数据观察 | 不适合作为当前单串口首版，会过早增加布局和组件成本 |

建议用 A 作为统一外壳，同时提供隐藏侧栏后的专注模式。C 在未来仪器视图中实现，不成为首版首页。

## 5. 信息架构与布局

```text
┌──────────────────────────────────────────────────────────────────────┐
│ DevToolNext │ 当前工作空间        命令/快速切换         共享状态 · 设置 │
├──────────────┬───────────────────────────────────────┬───────────────┤
│ 设备         │ 开发板 A · COM3 · 115200 8N1         │ 操作与证据    │
│ ＋ 添加连接  │ 已连接 · 本机控制 · 录制中            │ （按需打开）  │
│              ├───────────────────────────────────────┤               │
│ 串口设备 A   │ 日志 │ HEX │ 操作记录                │ 调用来源      │
│              │ 搜索 / 跟随 / 显示设置               │ 发送内容      │
│ 最近会话     ├───────────────────────────────────────┤ 等待条件      │
│ 今日录制     │                                       │ 完成判据      │
│ 故障样本     │             主要数据区域              │ 证据位置      │
│              │                                       │ 人工接管      │
│              ├───────────────────────────────────────┤               │
│ 设置         │ 命令输入 · 模式 · 换行 · 发送          │               │
├──────────────┴───────────────────────────────────────┴───────────────┤
│ 服务地址 · 连接状态 │ RX / TX │ 数据已保存位置 │ 查看/控制角色        │
└──────────────────────────────────────────────────────────────────────┘
```

- 顶栏约 44px；底栏约 26px；连接上下文与数据工具栏分别约 44px、36px。
- 左栏默认 224px，可收起；右栏默认隐藏，展开约 288px；实现时提供有最小宽度限制的拖拽调整。
- 默认不显示无意义空证据栏，有选中操作时再展开。独立原型为展示该设计，初始展开。
- 默认先聚焦一个设备；标签条结构允许未来多连接，但不把尚未实现的多连接伪装成已可用。
- 保存配置与连接实例分开：设备列表项能保存配置，不意味着始终打开连接。
- 关闭内容视图、断开设备、停止采集和退出服务是不同动作，文案必须准确。

## 6. 核心交互流程

### 6.1 连接

添加连接 → 选择端口与参数 → 建立连接 → 关闭配置浮层 → 主区显示设备上下文。

浮层展示常用参数；DTR/RTS 等放在高级选项，说明对复位的影响。连接期间给出进度与取消，失败保留参数和可理解的错误。已连接设备的参数修改需明确是否重连。

### 6.2 收发与阅读

输入固定在主区底部。普通日志模式使用显式输入框；文本与 HEX、编码、换行在邻近位置设置。发送前校验无效 HEX，不清空用户输入。发送成功表示驱动接受；设备完成状态另行表示。

日志按换行连续呈现，同一接收流跨块字符使用增量解码；未结束行继续更新，不因每次 read 返回而换行。日志、HEX 和原始记录之间保留映射，以便定位证据。

暂停只停止跟随或显示，不能停止保存。暂停时显示新增记录数量和“回到最新”；清空只影响当前显示。搜索必须标明当前窗口或全会话范围，不把局部搜索伪装成完整搜索。

### 6.3 人工、AI 与共享观察

区分访问权限和当前控制者：具有控制权限，不等于此刻拥有设备控制权。设备上下文持续显示“我控制 / AI 控制 / 他人控制 / 只读”。

AI 操作以任务条目展示发送内容、等待条件、超时、状态和证据，不增加内嵌聊天框。人工接管按钮靠近当前控制者，说明只阻止后续操作，不能撤销已发送字节。

只读用户保留搜索、查看、导出能力；输入区说明禁用原因。不能只改变按钮颜色而没有解释。

### 6.4 会话与证据

历史会话打开为明确的离线只读内容。离线回看不发送数据。主动重放必须独立设计，不复用“打开会话”动作。

点击操作跳转到对应记录范围；持续异步日志只能作为关联区间展示，不能自动证明因果。证据详情展示原始记录 ID、输入参数和完成判据。

## 7. 状态设计

| 状态 | 主区表现 | 操作与反馈 |
| --- | --- | --- |
| 无连接 | 连接入口、最近会话，不造数据 | 可连接或打开离线记录 |
| 连接中 | 原位进度，保留参数 | 防重复提交，可取消 |
| 已连接 | 持续更新输出、明确录制状态 | 可发送，分开显示驱动写入和命令结果 |
| 显示暂停 | 明显暂停提示、积累数量 | 回到最新，采集继续 |
| AI 控制（后续） | 控制者与当前任务 | 接管、取消后续动作、看证据 |
| 只读共享 | 角色与控制者清晰 | 输入区解释只读，不允许发送 |
| 异常断开 | 原因、时间和完整性标记 | 人工重连；不默默重发上次命令 |
| 写入失败 | 高优先级持久告警 | 显示采集已停止或不完整，不能继续显示正常录制 |
| 离线回看 | 历史会话标题与只读标记 | 搜索、证据与导出；不提供发送 |

独立原型用示例场景展示部分状态，不代表这些后端能力已实现。

## 8. 视觉与交互规范

- 中性灰为主，品牌强调色用于主操作和选中状态；绿/黄/红只表达状态，并配文字与图形。
- 深浅主题共享间距、布局和交互；终端对比度单独检查，不使用纯装饰渐变。
- 中文使用系统 UI 字体，日志使用可配置等宽字体并保留中文回退。
- 正文 13–14px，日志默认 14px/1.6；辅助信息不低于 11px。时间、字节数用等宽数字。
- 4px 基础间距；控件常用高度 32px，主要触控操作至少 40px；不依赖极小图标点击区。
- 一个稳定图标库，不用 Unicode 符号混充正式图标；图标按钮必须有名称和键盘焦点。
- 常用功能可见，高级配置渐进展开。动画只反馈交互，不做持续装饰动画。
- 文本对比按 WCAG AA 验证；状态不能只靠颜色；支持键盘导航和明确焦点。

快捷键建议：Ctrl+K 快速操作、Ctrl+F 当前视图搜索、Ctrl+Enter 发送、Esc 关闭浮层。仅在应用聚焦且目标上下文明确时响应，避免干扰浏览器和设备全屏程序。完整终端模式需另行设计按键转发规则。

## 9. 不同屏幕

- 1440px：左栏＋主工作区；右证据栏按需展开，日志保持主要宽度。
- 1024px：右栏为覆盖抽屉或底部面板，优先保证终端宽度。
- 768px 以下：设备列表改为抽屉；设备详情与工具栏分组，避免横向滚动整页。
- 手机优先满足局域网观察和接管提示；不追求同时显示三栏或完整终端键盘体验。
- 100% 与 125% 系统缩放分别检查，不能只验证大屏截图。

## 10. 实现路线与复用

建议后端保持现有服务契约，前端在原型确认后迁移到 React + TypeScript + Vite。增加前端构建步骤，但 EXE 仅打包编译后的静态资源，用户仍无需安装 Node。

可考虑 shadcn/ui 的对话框、菜单、标签和提示等基础组件，配合一致的图标库；组件库不负责工作台的信息架构。不必引入完整后台模板或首版完整 Docking 框架。

日志视图与完整终端是两种能力。先修正增量解码、组行、证据映射和有界显示；如果明确要求 vim/top 等全屏交互，再采用 xterm.js 并验证输入、尺寸、控制字符和回放边界。不能用自制 pre 元素宣称完整终端。

步骤：
1. 评审本轮原型：布局、深浅主题、参数入口、证据栏位置。
2. 定义组件和状态：设备项、上下文栏、日志视图、命令输入、操作条目、连接浮层。
3. 实现应用外壳并接现有 API，保持收发和录制链路。
4. 修复日志组行与证据映射，补齐断开、暂停和错误体验。
5. 后端 MCP/控制权就绪后接入对应真实状态，未就绪功能不显示为可执行。
6. 仪器阶段再增加波形等能力视图，不重新推翻工作台外壳。

## 11. 评审与验收

- 1366×768 默认布局下，主数据区可见高度至少 400px；避免大标题吞占空间。
- 无长驻大参数表、无大号静态计数卡、无无法使用的装饰导航。
- 连接和发送路径清楚，配置不超过一层浮层；错误能理解和恢复。
- 人工与 AI 操作能区分，权限和控制权能区分。
- 连续日志不因底层 read 分块产生人为换行；能回到原始证据。
- 暂停、搜索、清空和导出不影响采集正确性。
- 深浅主题、只读、断开、写入失败、键盘及窄屏分别检查。
- 原型中的模拟操作和虚构数据必须清晰标识，不作为功能完成证明。

## 14. 风格扩展（2026-10-31）

在同一信息架构上增加六种视觉方向，每种支持深浅主题，避免因数据与功能不同影响比较：

| 风格 | 特征 | 优先适用方向 |
| --- | --- | --- |
| Studio / 开发工作台 | 中性灰、柔蓝、标准密度 | 日常排障的默认候选 |
| Graphite / 石墨极简 | 近单色、直角、紧凑结构 | 输出优先，减少视觉干扰 |
| Lab / 精密实验室 | 冷白青蓝、分段标签、柔和圆角 | 仪器与测量方向 |
| Paper / 温润纸感 | 暖纸墨棕、行纹、文字层级 | 日志阅读与复盘 |
