# DevToolNext

一个可以接入AI的嵌入式设备调试工具

设备连接、控制与诊断工作台。当前为第一步基础版：Windows 启动入口、共用 Web UI、单串口收发、持久录制和会话查看。MCP、AI 控制权、离线插件安装和仪器接入尚未实现。

## 使用 EXE

运行 `dist/DevToolNext/DevToolNext.exe`，浏览器会自动打开本机工作台。EXE 的整个目录需要一起保留，不要单独移动 EXE。控制台窗口是服务进程，关闭浏览器不会停止采集；控制台按 Ctrl+C 正常退出。

默认地址为 http://127.0.0.1:8765。启动时生成临时控制密钥，通过 URL fragment 交给浏览器，随后从地址栏清除并保存在当前标签页的 sessionStorage。重启进程后旧密钥失效。

首次可以使用 `loop://` 回环测试：连接后发送内容，检查 RX/TX 和导出记录。它不是实际串口验证。真实设备请选择 COM 端口并确认参数；部分设备在打开串口时会因 DTR/RTS 变化复位，请先核对硬件。

## 局域网试用

在 PowerShell 中运行：

```powershell
.\dist\DevToolNext\DevToolNext.exe --host 0.0.0.0
```

控制台显示只读分享链接，将 `<本机IP>` 替换为运行 EXE 的电脑局域网地址。其他浏览器可以看相同会话，不能发送或断开设备。当前只提供本机控制、局域网只读这一简单授权方式，未实现多人控制权租约。复制控制链接会授予控制权限，不应作为只读分享。

本阶段 HTTP 未加密，仅供受信局域网试用；正式共享所需 HTTPS 与更细的用户管理尚未交付。Windows 防火墙可能需要允许专用网络入站。设备驱动只需安装在运行服务的电脑上。

## 源码运行和构建

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m devtoolnext
.\.venv\Scripts\python.exe -m pytest -q
.\build.ps1
```

当前构建环境为 Python 3.14.4 x86，产物为 Windows x86，在当前 Windows 11 上通过启动验证；其他 Python 版本及干净系统尚未验证。后续接入厂商仪器 SDK 时需按 SDK 架构选择 x64 环境。安装依赖和构建需要准备包；生成的发布目录包含运行依赖，正常启动不需要 Python 或互联网。`requirements-lock.txt` 记录当前完整开发环境依赖。

## 数据与边界

- 默认数据目录：`%LOCALAPPDATA%/DevToolNext`，使用 `--data-dir` 可指定。
- 原始字节以 SQLite BLOB 保存，记录方向、单调时间、墙上时间和稳定记录 ID；存储是可替换模块。
- 第一阶段选择 SQLite 同时保存事实数据与元数据，减少二进制与索引双写复杂性。后续有容量依据后再引入分段文件；这是一项相对初始方案的阶段性调整。
- 采集、持久化、UI 查询分离，有界队列满或磁盘写入失败时显式停止采集并提示。
- 非正常退出的会话在下次启动标记不完整；不能保证断电时未提交数据不丢失。
- 每次连接都会在日志目录写入一个可读 `.log`（时间戳 + 方向 + 文本），同目录可选写一个 `.jsonl` 保存原始字节；页面只保留最近 800 条记录供查看，搜索仅作用于当前窗口，清空和暂停只影响显示。数据库只保留最近 20 个会话供当前页面使用，长期存档以文件为准。
- 侧栏连接预设与录制数据保存在同一数据目录；连接成功时自动记录该组参数，删除预设不会影响已录制会话。
- 记录通过长轮询推送：服务端每落库一批（约 25 毫秒合并一次）立即应答，浏览器按动画帧合并重绘；状态栏每秒刷新一次。多个浏览器各用自己的游标读取，不竞争消费数据。当前未使用 WebSocket。
- 侧栏、详情栏、发送区可拖动分隔条调整大小，尺寸保存在浏览器 localStorage，只影响本机显示。
- 界面为日志查看器，未实现完整 ANSI/VT 终端、命令完成识别或 Shell 退出码；发送成功仅表示驱动接受数据。
- 串口已按独立适配器组织，但公共插件 SDK 尚未稳定。
- 首版不支持多个服务进程共用同一数据目录；退出现有实例后再启动。

自动测试使用真实 pyserial 软件回环，覆盖二进制收发、录制与分页、导出、重连、认证、只读权限、异常恢复和模拟磁盘失败。真实串口、长时高负载及无 Python 干净系统验收仍需执行。

已执行 11 项自动测试，并使用打包 EXE 和 headless Edge 验证界面收发、两个浏览器页面共享会话、暂停显示后继续采集及断开。浏览器测试入口为 `tests/browser_smoke.cjs`，需要另行准备 `playwright-core` 与 Edge；截图位于 `build/workbench.png`。

## v0.2.0：连接预设、可调面板与流畅输出

- 输出不再每帧重建整个列表：日志与原始记录改为增量同步 DOM，只增删变化的行；实测 528 行静止时一次重绘约 1.5 毫秒。
- 轮询间隔 500 → 300 毫秒，并按 `has_more` 连续追平积压；会话列表降为约每秒刷新，减少请求噪声。
- 侧栏新增"连接预设"：连接成功即自动记住该组参数，点击预设填入连接浮层，点 `↗` 直接重连，`×` 删除。
- 侧栏、详情栏、发送区均可拖动分隔条调整大小，双击复位，也支持聚焦后方向键微调；尺寸写入 localStorage，只影响当前浏览器。
- 文本发送框仍为单行输入，多行命令需逐条发送。

## v0.3.0：日志文件与可配置目录

- 侧栏移除“会话档案”：不再需要回看列表，连接即写文件，历史按文件管理。
- 每次连接在“日志保存目录”生成一个 JSONL：首行会话信息（端口、参数、版本、开始时间），中间每行一条记录（序号、墙上时间、单调时间、方向、Base64 字节），末行写入结束时间、是否完整（`complete`）与记录数。正常断开为完整，故障或异常退出标记不完整并带上原因。
- 目录默认 `%LOCALAPPDATA%/DevToolNext/logs`，可在侧栏底部“日志目录 → 设置”改成任意绝对路径（会校验目录可写）；修改只影响之后的新会话，“打开文件夹”可直接定位。
- 数据库只保留最近 20 个会话供当前页面查看，重启后旧会话自动清理；长期保存以 JSONL 文件为准。
- 文件按批 flush，不逐条 fsync；进程崩溃或断电时最后未刷出的少量数据可能丢失。页面上的“导出记录”仍可用于从浏览器下载当前会话。

## v0.3.1：流式输出

- 记录不再靠定时拉取：采集批次每约 25 毫秒落库并**主动唤醒**等待中的长轮询请求（`GET /api/sessions/{sid}/records/live`），浏览器收到即渲染；空闲时该请求最长等待 20 秒，连接结束会立即返回。
- 前端按 `requestAnimationFrame` 合并多次到达，避免一帧内重复重绘；行投影改为增量推进，只解码新记录，不再每次重算整个窗口。
- 实测（本机 loopback，headless Edge）：从发送到内容出现在界面，中位 **7 毫秒**、最大 12 毫秒；428 行窗口的静止重绘 **0.5 毫秒**。
- 状态栏（RX/TX、连接状态）仍每秒刷新一次，随直播响应同步更新计数，不额外发请求。

## v0.4.0：对齐常用串口工具的交互

- 发送区改为多行编辑：Enter 换行、Ctrl+Enter 发送；↑/↓ 翻最近 50 条发送历史（保存在浏览器）。
- 循环发送：设置间隔（50 毫秒–10 分钟）与次数（0 表示不限），点“循环发送”开始，按钮变“停止循环”；断开连接会自动停止。
- 显示选项：时间戳开关、日志字号四档；设置保存在浏览器，不影响其他观察者。
- 终端渲染：解析 ANSI SGR 颜色（16 色 + 粗体），按终端语义处理退格（`\b` 覆盖前一字符），其余 CSI/OSC 控制序列不显示也不污染复制内容；原始字节仍完整保存在证据与 JSONL 中。
- 线路控制：DTR / RTS 可手动切换（部分板卡会因 DTR 变化复位），状态显示在按钮上。
- 快捷键：Ctrl+Enter 发送、↑/↓ 历史、Ctrl+F 搜索、Ctrl+L 清屏。
- 尚未实现：完整 VT100 终端（光标移动、清屏、滚动区）、HEX 视图的 ASCII 侧栏、断线自动重连、协议解析。

## v0.5.0：日志文件、Telnet/SSH、多窗口

- 会话产物改为可读的 `.log`：首部写明会话号、目标与开始时间，之后每行“时间 方向 文本”（ANSI 颜色码会被剥离），结尾写入结束时间与是否完整。设置里可以勾选“同时保存原始 JSONL”，用于保留无损字节。
- 连接类型新增 Telnet 与 SSH：新建连接时选择类型即可，串口字段自动收起；SSH 支持密码、私钥文件与 ssh-agent，主机密钥采用自动信任（本地工具，首次连接不做指纹校验）。
- 密码只在内存中使用：不写数据库、不写日志、不出现在状态接口，也不会被连接预设保存。
- 多窗口：顶部标签栏可以同时打开多个连接（串口 + Telnet + SSH 混合），各自独立采集、独立日志文件；切换窗口时日志与证据互不串数据，关闭标签即断开该连接。
- 依赖新增 `paramiko 2.12` 与 `cryptography 35`（32 位 Python 3.14 可用的最后一批 win32 预编译包），已随 EXE 打包。

## v0.6.0：终端交互视图（串口同样适用）

- 新增“终端”视图并设为默认：输出与输入在同一屏，点一下终端就能直接敲键，不用再去底部发送框（终端视图下发送框自动隐藏）。
- 按键映射：可打印字符按 UTF-8 发送，Enter → `CR`，Backspace → `0x7F`，Tab、Esc、方向键、Home/End/Delete 按 ANSI 序列发送，Ctrl+字母 → 对应控制码（Ctrl+C 为中断），支持 Ctrl+V 粘贴（换行转换为 CR）。
- 终端按行渲染并保留 ANSI 颜色；回车按行结束处理（`CR` 与 `CRLF` 等价），退格覆盖前一字符，光标跟随输入位置。
- “本地回显”开关（默认关闭，与 SecureCRT/MobaXterm 一致）：设备不回显时打开即可看到自己输入；网络会话由远端回显，不建议开启。
- 串口 / Telnet / SSH 三种连接行为一致；原有的“日志 / HEX / 原始记录”视图保留，按方向取证、查看原始字节。
- 终端里的按键同样作为 TX 记录写入 `.log`、`.jsonl` 与数据库，证据链不变。
- 修复标签栏点击事件误绑到 `body` 导致每次点击都重置视图的问题。

## v0.7.0：MCP 服务（让 Agent 驱动串口 / Telnet / SSH）

服务进程内置一个 MCP 端点，Agent 可以直接建连接、发命令、读回复：

- 端点：`POST http://127.0.0.1:8765/mcp`（JSON-RPC 2.0 / MCP Streamable HTTP，也支持 `?token=` 查询参数）。
- 鉴权：请求头 `Authorization: Bearer <控制密钥>`；用只读密钥连接时，只有只读工具可用，发送/建连会被拒绝。
- 工具：
  - `list_connections` / `connection_info` / `list_serial_ports`
  - `open_connection`（serial / telnet / ssh，含串口参数、SSH 用户名密码或私钥）
  - `close_connection`
  - `send_command`（文本或 HEX，可指定 `none/cr/lf/crlf`；返回发送前游标）
  - `read_output`（按游标读取，返回文本 + HEX）
  - `wait_for_output`（阻塞等待提示符/`OK` 等，支持正则与超时）
- 典型流程：`open_connection` → `send_command`（拿到 `cursor`）→ `wait_for_output(after=cursor)` → `read_output`。
- 两种接入方式：
  - HTTP：`{"url": "http://127.0.0.1:8765/mcp", "headers": {"Authorization": "Bearer <控制密钥>"}}`
  - stdio（面向只支持 stdio 的客户端）：`DevToolNext.exe --mcp-stdio --mcp-token <控制密钥>`，通过桥接转发到本机实例。
- 控制密钥等同于本机操作权限：不要把它或 `--host 0.0.0.0` 的地址暴露到公网；不需要时不要启动 MCP 客户端配置。

## v0.8.0：界面收敛为「终端 + 发送框」

- 移除“日志 / HEX / 原始记录”三个视图和右侧证据面板，界面只保留终端与发送区，和常见串口软件一致。
- 原始字节没有被丢弃：`.log`、`.jsonl`、导出接口与 MCP 的 `read_output` 仍能拿到完整记录；只是界面不再提供逐条取证面板。
- 换行修正：连续回车（`CR CR LF`）折叠成一次换行，解决部分设备每行后面多一个空行的问题；单个 `CR`、`LF`、`CRLF` 仍各算一次换行。
- 发送区换行默认改为 **CR**：SSH/Telnet 的行规程把 CR 与 LF 都当回车，选 CRLF 会一次敲两个回车、多出一个空提示符。
- 终端提示、字体大小、编码保留；侧栏拖动、连接预设、多窗口标签、日志目录设置不变。

## v0.9.0：终端回车修正与 MCP 开关

- 终端只显示设备输出，不再有“本地回显”选项：开启它时，自己按的回车和远端回显会各占一行，表现为“每次回车多一行”。现在输入只走远端回显，和主流终端一致。
- 光标只在当前行显示：此前某一行曾经是光标行时会残留光标块，导致一屏出现多个蓝色方块。
- MCP 网络接口加了开关（侧栏底部 `MCP`）：默认开启，关闭后 `/mcp` 直接返回 404。
- MCP 对话框里直接给出可粘贴的客户端配置，并支持一键复制：

```json
{
  "mcpServers": {
    "devtoolnext": {
      "type": "http",
      "url": "http://127.0.0.1:8765/mcp",
      "headers": { "Authorization": "Bearer <当前浏览器使用的密钥>" }
    }
  }
}
```

- 复制内容用的是当前页面登录的密钥：控制密钥可建连与发送，只读密钥只能读取。

## v0.9.2：回车多一行、访问密钥持久化

用 COM5 抓到的真实字节：

```
0d 0a  1b5b3f323030346c  0d  1b5b3f3230303468  "kickpi@kickpi:~$ "
↑回车   ↑bracketed paste关  ↑回到行首        ↑bracketed paste开
```

第二个 `0d` 是 **carriage return（回到行首）**，readline 每次重绘提示符都会发它，不是换行。之前把每个 `CR` 都当换行，所以每按一次回车就多出一行。

- 终端改为标准语义：`CR` = 回到行首覆盖、`LF` = 换行、`CRLF` = 一次换行。
- 顺带修正：只有 `CR` 的设备不会再被拆行，而是按终端规则覆盖当前行（这类设备建议改成 `CRLF` 输出；确实需要“CR 换行”的话可以再加开关）。
- 回归用例直接用上面这串真实字节，断言只产生一次换行。
- 访问密钥改为持久化：首次启动写入 `<数据目录>/tokens.json`，之后重启沿用同一密钥，浏览器地址与 MCP 配置不再失效；需要换密钥时加 `--rotate-tokens`，也可用环境变量 `DEVTOOLNEXT_CONTROL_TOKEN` / `DEVTOOLNEXT_VIEW_TOKEN` 指定。

## v0.1.1：新版工作台界面

正式界面已采用新工作台布局，启动后顶部可选择 Studio、Graphite、Lab、Paper、Midnight、Terminal 六种风格，并独立切换深浅主题。外观偏好保存在当前浏览器，不影响其他局域网观察者。

- 左侧：当前设备与最近 100 个会话，可搜索并打开历史记录。
- 连接参数：点击"连接"打开浮层；已连接时参数只供查看，修改需先断开。
- 中间：日志、HEX、原始记录三种视图。日志按连续字节组行；不是完整 ANSI/VT 终端。
- 右侧：点击日志或原始记录打开证据详情，展示真实记录编号、时间、长度和 HEX；不包含模拟 AI 任务。
- 日志行对应的记录范围可能含邻近行或解码边界数据，未实现精确到字符的字节偏移映射；原始记录视图保留逐条分块。
- 日志窗口最多显示最近 800 条原始记录派生的 1500 行，单行超过 16K 字符会标记显示截断，原始记录和导出不截断。
- Enter 或 Ctrl+Enter 发送，Ctrl+F 搜索当前窗口；暂停显示不停止采集。
- 当前仍无 MCP、AI 控制权及多人控制权租约，界面不将这些能力显示为已交付。

新增无依赖日志投影检查：`node tests/transcript.cjs`。浏览器检查覆盖真实软件回环、记录详情、导出、六种风格、外观持久化、只读与窄屏。
